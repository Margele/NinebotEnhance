# Ninebot Enhance 使用手册

各功能的完整说明；项目简介见 [README](../README.md)。

## 功能

- 在车辆的“仪表投屏导航”卡片直接启动投屏，无需输入目的地发起导航。
- 在独立虚拟显示器运行指定应用，整帧尺寸取自车辆仪表的投屏配置（M5P 为 **848 × 480**），虚拟屏默认 **640 × 440，160 DPI**，可修改。“保持 DPI”默认勾选：DPI 仍决定布局（640 × 440 dp），但虚拟屏按手机的密度、按比例放大的逻辑分辨率创建（520 DPI 的手机上是 2080 × 1430），模块采集时再缩回 640 × 440 放进整帧；手机密度与布局 DPI 相同时不缩放。
- 使用“无（投屏）”模式，通过系统录屏选择分享单个应用或整个屏幕，无需 Root 或 Shizuku / Sui 授权。
- 虚拟屏与模块采集目标为 **20 FPS**，读取最新画面，实际帧率可在统计和日志中查看。
- 设置中选择启动应用，投屏期间不显示启动器；应用离开副屏后可一键重新启动。可以先在手机上设好导航再投屏：高德被搬到副屏时会被系统重建并回到首页，模块随后用高德自己的路线规划链接把同一个目的地、同一种出行方式（摩托车 / 驾车 / 骑行 / 步行）再规划一次，副屏上出现路线页后点开始导航即可；两分钟内没有导航数据或已到达则不重新规划。高德把屏幕密度留在进程里：手机上已经开着的高德搬到副屏、或投屏结束回到手机后，布局可能错位，强制停止一次高德即可恢复；“保持 DPI”（默认勾选）让副屏密度与手机相同，两个方向都不再错位。
- 支持横屏应用布局、手机息屏后保持虚拟屏运行。
- 虚拟显示器不依赖车辆：随时启动，在手机上预览和操作，投屏结束或收起预览后仍保留，直到退出九号出行。
- 预览支持触摸、返回、旋转画面，以及使用手机当前输入法输入文字。
- 预览工具栏的「深色 / 浅色」切换仪表的昼夜主题：仪表自己画的顶部状态栏和模块的卡片一起换色，整帧背景分别取设置里的深色背景和浅色背景。选择会保存，每次投屏开始时发给仪表，九号自己按手机深色模式发的那一次也改成这个选择。
- 支持 **自动、Root、Shizuku / Sui、无（投屏）**四种方式，开始前检查所选模式和车辆状态。
- 查看采集、编码、发送提交的会话统计，以及原会话编码分辨率、目标 FPS 和码率日志。
- 手机预览可叠加实时统计：编码码率、发送带宽、帧率与目标帧率、帧数、队列丢帧和仪表丢包反馈；只画在手机上，不进入发给仪表的画面。
- 设置中的“设置覆盖”里，“覆盖虚拟屏”勾选后按填写的宽、高、DPI 建立虚拟屏，不勾选按仪表形状取默认值（五寸 640 × 440 @160，半屏 240 × 300 @160）；深色 / 浅色背景、“保持 DPI”也在这里。它还可强制原编码器的码率（100 kbps–3 Mbps）和帧率（5–30 fps），保存后对正在运行的投屏立即生效；“覆盖分辨率”只改模块自己合成的整帧（预设“半屏仪表 240 × 320”“五寸仪表 848 × 480”或自定义 160–1920 的偶数），不改九号发给车辆的编码尺寸，从下一次投屏开始生效。
- 设置中的“隐藏功能”可让九号“转把设置”页里被车辆功能位隐藏的“双向转把 倒车 / 无缝倒车 / 辅助制动”三项显示出来，也可以把九号只给外接仪表车型布局的“仪表按键”遥控卡片（上下左右、中键、音量加减，短按 / 长按）放到车辆页投屏按钮下方，或让九号自己因“不支持巡航”而隐藏的原版巡航按钮重新显示（点它走的是不经模块的九号原生巡航投屏）；这三项模块不向车辆写任何东西，拨动开关和按键仍由九号自己下发，固件未开放的功能可能不生效。
- 手机导航上仪表：模块作用域包含高德地图、腾讯地图和百度地图，在这三个 App 里只挂观察钩子。高德导航时，引擎的转向 / 距离 / 路名状态经模块服务转到九号进程，车辆投屏期间按九号地图导航页的格式写给仪表（“控件管理”底部的“手机导航上仪表”开关，默认开），仪表在巡航画面上显示转向箭头、剩余距离时间和路名；腾讯、百度目前只记日志。导航 App 的行为不被修改。
- “关于”里调试模式旁的“巡航导航测试数据”是一个实验开关：打开后，模块的车辆投屏会话期间按九号地图导航页的格式向仪表写一段 3 km 的脚本导航数据（全程距离、当前 / 下一路名、每秒一次的剩余距离 / 时间 / 转向图标 / 已行驶信息），用来验证仪表在巡航模式下是否显示蓝牙导航数据。这是模块唯一的写指令路径，只写仪表的导航显示数据，不碰车辆设置。
- 右下角常驻手机电量、充电、单卡或双卡信号，以及已连接的 Wi-Fi 图标；没有 Wi-Fi 时同一位置改显示当前移动网络类型（5G/4G/3G/2G，需已授权手机信号）。
- 右侧紧凑显示专辑图、歌名、歌手和播放进度，暂停图标显示在专辑图上；默认只在切歌或播放/暂停变化时展开，几秒后自动收起（可关闭，可拖动设为 3–15 秒），没有音乐时整个卡片隐藏；把音乐卡片的条件设为“始终”后，没有媒体会话时卡片也保留，标题显示“无播放”。
- “胎压”卡片一行显示前后胎的胎压和胎温；“电压”卡片显示电池电压，并可选带最近 10–60 秒的电压曲线（默认开启，30 秒）。胎压复用九号已接收的监测数据；投屏期间九号详情页会停止轮询，模块通过九号自身的蓝牙读取接口补读，默认胎压每 30 秒、电压每 1 秒一次。只要卡片开启就会读取；前后胎和曲线图在“控件管理”里各自的“设置”中调整，读取间隔在“数据读取设置”中调整。
- 选择允许显示通知的 App，通知从右下角滑入；显示时长 5–30 秒、宽度 180–600、同时显示 1–5 条都用拖动条调整。
- 速度、功率组件（默认关）：与电压卡片同样大小，显示仪表读到的车速（km/h）和电机功率（W，有符号值，动能回收时为负），各自可选曲线图（默认开）和曲线时长（10–60 秒，默认 30 秒）。
- “控件管理 → 数据读取设置”集中调整胎压、电压、速度、功率四个读取间隔（胎压 5–60 秒，其余 0.5–15 秒、步长 0.5 秒，默认 30 秒与 1 秒）；每项只在有组件或驻车避让需要时才读取。
- 坡道驻车避让（默认开）：模块按设定间隔读取车速和电机功率，车速不超过阈值、功率处于最小与最大阈值之间并持续到最短时间时判定为坡道驻车（仪表显示 H 并在右下角弹出“拧动油门解除坡道驻车”）。此时凡是按当前位置会被提示框盖住的卡片（含通知）都保持高度滑到提示左侧，其余卡片按原顺序重新堆到提示上沿；解除条件（包括读数过期 3 秒）同样要连续满足最短持续时间才恢复；阈值在“控件管理 → 驻车避让 → 设置”里拖动：最小功率 50–200（默认 100）、最大功率 200–500（默认 300）、车速 0–3 km/h（默认 0 即必须完全静止）、最短持续 1–5 秒（默认 1，进入和解除都要满足）。判定用的车速和功率只取车辆自己的 `rSpeed` / `rPower` 寄存器，与 BMS 无关，“功率”卡片勾了“BMS 优先”也不影响。虚拟显示器预览里会画出这条提示的示意。
- BMS 管理：在“控件管理 → BMS → 管理”里扫描并绑定 DL-BMS（也可手填地址），设定轮询间隔（1–10 秒）后保存，模块自行完成密钥交换并轮询电池数据；“控件管理 → BMS → 设置”里为每个字段选行（隐藏 / 第 1–3 行）并拖动排序，底部预览即仪表上的样子，空行不占位；未连接时卡片只写“BMS 未连接”。“电压”“功率”卡片的选项里勾“BMS 优先”后，BMS 有新读数时用它的值，否则回到仪表读数；显示条件新增“BMS 已连接”。
- 大灯控制：在“控件管理 → 大灯 → 管理”里扫描并绑定 TX 灯控（广播名 MOTORE 开头），填 6 位密码后保存，模块会立刻连上并握手，屏幕上显示认证结果。蓝牙权限由模块自己申请，和九号的车辆连接互不相干。绑定后“大灯”控件显示仪表侧的实时高度，连不上时显示“未连接”。没有音乐在播放时，手机音量加减键改为调节大灯高度，原音量会被立即还原，不会真的改变音量（按住不放会连续一档一档地走灯而音量始终不变）；正在播放音乐时音量键照常调音量。同一页里设置档位数、音量键开关和反转方向：档位数把设备上报的行程（上下限之间）平均分成几档，一次按键走一档，行程顶端始终显示为 100%（比如某台灯只能升到 73，73 就是 100%）；反转方向把灯光的高低两端对调，只在打开音量键调节时可用，关掉音量键开关后自动置灰。“大灯”控件的卡片背景会按当前亮度画一条进度条（50% 就填一半），数值是换算后的百分比。
- 大灯和 BMS 的蓝牙链路只在九号出行的界面可见、正在投屏或模块自己的大灯 / BMS 界面打开时保持；九号退到后台、投屏结束后几秒内断开，模块不在后台保持连接，灯控和保护板此时可以被别的 App 连接，音量键也恢复为普通音量键。回到九号或开始投屏后自动重新连接。
- 更新提示：模块进程最多每 6 小时向 GitHub 查询一次最新 Release（这是模块唯一的网络访问，只发请求、不传数据）；发现新版本时在车辆页弹一次窗，可打开 Releases 页面或忽略该版本，设置页顶部也会出现“更新到 x.y.z”按钮。不自动下载。
- 触摸屏管理：设置页里的“触摸屏管理”列出接在手机上的外接触摸屏（USB 或蓝牙，手机自己的屏幕不在列表里），选一块、选好安装方向（0° / 90° / 180° / 270°）后保存；USB 面板会弹一次系统的 USB 授权，允许后模块在投屏期间持有该设备，面板不会因 USB 自动休眠而失灵（拔掉重插后系统会再问一次）。投屏期间辅助进程独占这块面板，面板量程对应整块仪表画面（整帧），落在应用画面里的触摸换算后注入副屏，落在应用画面外（顶部色带、右侧卡片区）的按下会被忽略，手机屏幕不响应它；投屏结束面板恢复原状；中途拔掉再插上会自动续上。“显示触点”（默认开）在仪表画面和手机预览上按下的位置画一个圆环，抬起后淡出。点不准时用预览工具栏的“校准”（虚拟显示器预览和车辆投屏都有，绑定的触摸屏接上、辅助进程打开了它才出现）：点一下进入校准，画面上依次出现 5 个带编号的靶点，在面板上逐个点，全部点完自动保存并立即生效，再点“取消校准”可中止；校准后面板的方向和偏移都由校准结果决定，“旋转”只在未校准时起作用。“解除绑定”清掉选择和校准。
- 在“控件管理”中分别开关手机状态、胎压、电压、音乐、通知、音量、大灯和坡道驻车避让，胎压、电压、音乐、通知各带“设置”按钮；控件的出现、消失、移动和尺寸变化都有动画，通知进入时将其他控件向上推，退出后恢复。手机音量变化时，画面左下角车机音量图标上方会短暂显示一条竖向音量条。
- “控件管理”里的列表按画面从上到下排列，拖动行首的“≡”可以改变卡片（含通知块）的堆叠顺序；排在通知下方的卡片不会被通知顶起。列表中间有一条可拖动的“右侧”分界线：线下方的卡片放在原来的右侧一列，线上方的卡片放到紧贴其左边的第二列（右边缘 633），用来躲开仪表右上角的遮挡；通知只能留在右侧。有通知时左列整体抬到通知块之上，驻车避让时左列抬到被挤出的卡片和提示框之上。右列堆得过高、上方的卡片伸进仪表右上角的原车遮挡区（640,44）–（842,254）时，被遮住的卡片自动挤到左列，按原来的高度插到左列合适的位置（可以在两张卡片之间）一起堆叠，右列变矮后自动回到右列。每个控件都有“条件”：始终显示、条件变动时（音量变动、歌曲变更、播放状态变更后显示设定秒数）或满足条件时（速度、功率（按绝对值）、电压、音量、前后胎压、前后胎温处于区间，或正在播放音乐；区间用双头滑块设置，拖到最左端或最右端即不设该侧界限）。条件需要的胎压也会自动读取。音乐的自动隐藏并入“条件”，默认仍为歌曲变更或播放状态变更后显示 5 秒；条件需要的速度、功率、电压会自动读取。

## 适配范围

| 项目 | 支持范围 |
| --- | --- |
| 九号出行 | 支持 **6.10.10（610104038）** 和 **6.10.11（610114116）** 两个版本，其他版本禁用画面替换 |
| Android | **Android 14–16（API 34–36）** 为当前适配范围 |
| LSPosed | 支持 libxposed API 101 或后续兼容 API |
| 作用域 | **九号出行**（`cn.ninebot.ninebot`）以及高德地图、腾讯地图、百度地图（导航数据上仪表），无需系统框架 |
| 授权方式 | Root、提供 API 13+ 的 Shizuku / Sui，或系统录屏授权 |

所有模式均需启用 LSPosed 模块。Root / Shizuku / Sui 用于创建和控制独立虚拟屏；“无（投屏）”使用系统录屏。Root 及以 Root 运行的 Shizuku / Sui 需要设备支持 `su 2000`；辅助进程默认以 shell 身份运行，勾选“不降权”后以 root 身份运行。其他手机、系统和仪表的行为可能不同。

## 安装与使用

1. 安装 `NinebotEnhance-1.1.5.apk`。
2. 在 LSPosed 启用 **Ninebot Enhance**，作用域勾选 **九号出行**；要把手机导航送上仪表，再勾选高德地图、腾讯地图、百度地图。
   - HyperOS / MIUI、ColorOS / OxygenOS / realme、vivo、华为 / 荣耀：到系统的应用管理里允许 Ninebot Enhance“自启动”和“允许被其他应用关联启动”，后台耗电 / 省电策略设为不限制，并从桌面打开一次 Ninebot Enhance。模块没有常驻进程，九号每次都通过绑定模块服务把它拉起来；系统拒绝时设置页会显示“系统未接受服务绑定”并弹出自启动提示，模块会按 1、2、4、8 秒退避重试，同时用一次 ContentProvider 调用尝试唤醒自己。授予通知使用权后模块进程由系统保持存活，绑定即刻成功。
   - 任何系统：如果对九号出行启用了「隐藏应用列表」之类的功能（如 Hide My Applist），九号会查不到 Ninebot Enhance，服务绑定必然失败；设置页和弹窗会提示这一点，请把 Ninebot Enhance 加入该功能的例外。
3. 强制停止并重新打开九号出行，进入车辆信息页，连接车辆后在“仪表投屏导航”卡片底部的按钮行点击“设置”，或随时点击页面底部的“拥有爱车第 x 天”一行。模块没有独立桌面入口。
   - 首次打开设置会要求输入「我已知本项目免费开源在GitHub。」，点右侧「一键输入」即可填入，只需一次。
4. 打开“授权方式”，完成授权并保存。
5. 虚拟屏模式下选择启动应用、设置显示参数并保存；录屏模式会隐藏这些选项，开始时通过系统窗口选择分享内容。修改设置前，先结束当前投屏。

### 授权方式

| 方式 | 使用方法 |
| --- | --- |
| 自动 | 优先使用已授权的 Shizuku / Sui，其次检查 Root |
| Root | 在 KernelSU / Magisk 等管理器中允许 Ninebot Enhance；设置中可点“申请 / 验证 Root 权限” |
| Shizuku / Sui | 先启动对应服务，再点“授权 Shizuku / Sui”，允许后保存 |
| 无（投屏） | 无需 Root / Shizuku / Sui；每次开始后，在系统录屏窗口选择单个应用或整个屏幕 |

已有 Root 连接会被复用；服务重启或连接失效后，投屏前自动重新验证。缺少授权时会提示前往设置，完成授权后重新点击投屏。Shizuku / Sui 被拒绝且不再询问时，需要在其管理界面为 Ninebot Enhance 开启权限；Sui 管理入口见 [官方说明](https://github.com/RikkaApps/Sui#management-ui)。

投屏画面正常但副屏无法触摸、外接触摸屏和键盘也无效，日志里反复出现 `Injecting input events requires ... INJECT_EVENTS`：这是系统不给 shell 身份注入权限。小米 / HyperOS 上到开发者选项打开“USB 调试（安全设置）”即可，它管的就是通过 USB 调试模拟点击的权限，和是否插线无关。模块检测到这条错误时会弹窗说明并提供“打开开发者选项”按钮，每次运行只弹一次。

“不降权”复选框是另一条路：默认辅助进程用 `su 2000` 降到 shell 身份运行；勾选后保持 root 身份（uid 0），不再受这项限制。只对 Root，以及以 Root 运行的 Shizuku / Sui 生效；ADB 方式启动的 Shizuku 本身就是 shell，无法提升。勾选或取消后，下次开始投屏会重新验证 Root；日志里的 `DAEMON uid=` 和 `backend=Root 授权的 root 辅助进程` 可确认已生效。

### 车辆投屏

车辆页“仪表投屏导航”卡片底部一行是三个按钮：最左的虚拟显示器图标、“全屏投屏”和“设置”，卡片随车辆蓝牙连接出现，按钮跟着卡片走，“全屏投屏”一直可点。点击“全屏投屏”后模块检查所选方式，然后直接调用九号原巡航入口（九号把它隐藏了也一样调），是否连接、车型是否支持、是否开机都由九号自己的巡航逻辑检查；页面上根本没有巡航入口时提示“巡航入口不可用”。开机检查通过且巡航页面就绪后，虚拟屏模式把画面接到已经在跑的虚拟显示器上，没有就先创建并打开所选应用；“无（投屏）”模式打开系统录屏授权，确认后将录制画面交给九号原编码及发送流程。车辆关闭、检查失败或状态未知时不启动画面采集。等待期间可再次点击按钮取消。“停止投屏”只断开投屏，虚拟显示器和里面的应用照常运行，可以再次投屏。

录屏模式下，直接在手机上操作所选应用或整个屏幕，画面尺寸随录制内容自动调整。单应用录制只分享系统选择器中选定的内容；更换分享目标需要结束后重新开始。每次启动都需要系统确认；锁屏或从系统结束录屏会终止当前会话，参见 [Android 录屏说明](https://developer.android.com/media/grow/media-projection)。

### 虚拟显示器与输入

点击“启动应用”会打开模块的应用选择器。系统询问应用列表权限时，请允许 **Ninebot Enhance** 读取；若之前拒绝过，可点“应用列表权限”进入系统应用设置，授权后返回刷新。此选择器只列出可启动的应用，不需要先授予通知使用权。

虚拟屏模式下点最左的虚拟显示器图标即创建虚拟显示器、打开所选应用并弹出手机预览，无需车辆开机或连接蓝牙，不投屏就不向车辆发送画面。返回键和预览工具栏的“关闭”只收起预览，虚拟显示器、其中的应用和外接触摸屏照常运行，再点同一图标（运行中显示为强调色）重新打开。虚拟显示器只在退出九号出行（进程结束或最后一个页面关闭）时关闭。“无（投屏）”模式没有虚拟显示器，车辆页不显示虚拟显示器图标、设置里不显示“触摸屏管理”；投屏时才开始录屏，投屏结束录屏即结束。

整帧（合成画布）的宽高不再手动设置，而是读取九号缓存在自己外部存储目录里的仪表投屏配置 `<车架号>_screen_cast_config.nb`，取其中的编码尺寸（M5P 为 848×480，竖向半屏仪表为 240×320，七寸仪表为 1024×600，板子把编码高度对齐成 608 时也按七寸处理），每边 160–1920 都接受；没有读到配置时沿用 848×480。竖向整帧（高大于宽，如半屏仪表）用半屏布局：卡片列铺满整帧宽度、按顺序单列堆在底部，通知最宽为列宽，不做驻车避让（“驻车避让”变灰）也不画右上角仪表遮挡；虚拟屏高度默认留出顶部 20 像素（240×320 时为 240×300）。横向整帧缩到 848×480 参考尺寸的 40% 以下时不画仪表卡片。虚拟屏宽高决定应用的实际分辨率，超出整帧时自动缩小到整帧以内。虚拟屏不缩放、不裁剪，靠左对齐、贴在底部预留之上，剩余区域使用背景颜色。五寸默认虚拟屏为 640×440，坐标为 (0,40)：顶部预留 40 像素，右侧与仪表卡片的边界留出间隔。七寸（1024×600）默认虚拟屏为 760×496，坐标为 (0,48)：顶部 48 行留给仪表状态栏图标，底部 56 行留给仪表自己的电量 / 续航信息带（板子报 608 时是 64 行，多出的 8 行在屏外），右侧 x 770–960 是卡片列，仪表右下角的挡位 / 车速面板和 NOS 竖条都不被盖住；卡片不放大，驻车避让在七寸上暂不可用，音量条在整帧左缘。「设置覆盖」的分辨率预设多了「七寸仪表 1024 × 600」。修改尺寸前需结束投屏。

虚拟显示器预览的工具栏是“返回、横屏、输入法、深色 / 浅色、关闭”，绑定的触摸屏在线时多一个“校准”。“横屏”把整个预览窗口转成横屏（跟随系统的横向自动旋转），“还原”或收起预览转回来；这只改手机上这个窗口的方向，不改变副屏应用或仪表画面的方向。巡航页的仪表预览嵌在九号页面里，它的“横屏”只旋转预览画面，最后一个按钮是“结束”（停止投屏）。输入时先点击副屏输入框，再点“输入法”。中文和 emoji 转发可能临时使用剪贴板，具体行为见 [预览与输入](preview-input.md)。

### 通知与手机状态

在“控件管理”中点击“通知”一行的“设置”打开通知设置，先为 **Ninebot Enhance** 授予系统“通知使用权”。授权后列出当前用户的全部已安装 App，包括没有桌面入口的应用；可搜索应用名或包名并勾选，已勾选的 App 排在顶部。打开“显示通知”总开关，设置显示时长后保存。默认关闭通知展示，应用默认不勾选；显示时长默认为 15 秒，可拖动滑块调整为 5–30 秒。

“通知宽度”控制每条提示的宽度，默认 312，可拖动调整为 180–600，按 848×480 参考坐标计算，随整帧等比显示。“最多同时显示”默认 3 条，可拖动调整为 1–5 条。最新通知位于最右下方，与右侧控件右边缘对齐，之前的通知向上排列。通知进入和退出时，右侧其他卡片随之整体上移或下移。

通知以图标、加大字号的标题和正文以及 App 名称显示，底部细条表示剩余时间。新增消息独立显示、单独计时，同一 App 连续发来的消息不会互相覆盖。达到“最多同时显示”条数后，新通知先移出最早的一条；调低条数时多出的旧卡片立即退出，等待中的通知在名额空出后进入。Telegram 等聊天应用刷新旧通知时，已展示的消息不会重复弹出；移除手机通知会同步移出对应提示。开始投屏前的历史通知不会重放。关闭总开关、修改通知设置或撤销通知使用权后清空当前提示。

启用手机状态控件后，手机状态完整显示，不随通知收缩。在通知设置中点“授权手机信号”，授予模块电话状态权限，用于读取卡槽、信号强度和移动网络类型。未授权或读取失败时显示未知状态；电量和 Wi-Fi 仍可显示。模块不读取手机号、联系人、SSID 或位置，不需要将其他 App 加入 LSPosed 作用域。

音乐控件通过系统 [MediaSessionManager](https://developer.android.com/reference/android/media/session/MediaSessionManager#getActiveSessions(android.content.ComponentName)) 读取当前媒体会话，需要模块的通知使用权，不受通知总开关和通知 App 勾选列表限制。优先显示正在播放的会话，暂停时在专辑图中央叠加暂停图标并保留歌曲信息。默认开启“自动隐藏”：只在切歌、切换播放器或播放/暂停状态变化时展开，经过“展开时长”（默认 5 秒，可拖动设为 3–15 秒）后收起；关闭自动隐藏则只要有曲目就一直显示。没有音乐或播放已停止时整个音乐卡片隐藏，其他控件自动补齐空位；播放器未提供的信息显示未知。音乐控件仅展示信息。专辑图只取媒体元数据中的图片，不访问图片网址，音乐信息不写日志或磁盘。

“胎压”和“电压”是两张独立卡片，自下而上的顺序固定为手机状态、音乐、胎压、电压，都靠右对齐。胎压卡片一行显示 `前 2.4 bar 29 ℃  后 2.6 bar 30 ℃`，高 28，与其他卡片同宽（190）；在其设置中可分别勾选前胎、后胎，全部取消时不显示卡片。电压卡片第一行显示 `电压 79.3 V`；打开“曲线图”后高 84，下半部分绘制最近“曲线时长”（默认 30 秒，可拖动设为 10–60 秒）内每次收到的电压读数曲线（纵向自动缩放并标出区间最高、最低值），关闭曲线图则只有一行并按内容取窄宽度。胎压需要九号已绑定监测器并收到数据，模块观察九号原生解析器的蓝牙回复，以及车辆未连接蓝牙时的云端数据，不自行连接传感器或请求服务器，重复的云端数值不算新数据。电压优先取仪表板测得的总线电压 `rVrlaVoltage`（寄存器 177，10 mV），其次才是电池位 BMS 寄存器 `rVoltage` / `rVoltage2` / `rVoltage3`：实测锂电 M5 P 的 BMS 寄存器只返回标称 72.00 V，而仪表板寄存器跟随实际电压。模块被动观察九号自己轮询的 `rBool`，按其中的电池位标志决定要读哪个 BMS 寄存器；仪表板寄存器 90 秒内有回复时，BMS 寄存器只写日志不上卡片；连续两次无回复的指令在本次会话内不再发送。胎压实时帧 `rTirePressureRealTimeInfo` 也在同一处解码。九号详情页在投屏期间会停止自己的周期读取，因此胎压和电压的设置里各有“主动读取”开关：打开后，车辆投屏或虚拟显示器运行期间只要车辆已连接，模块就通过九号自身的 `sendCommand` 读取这些只读指令，胎压按“胎压更新间隔”（默认 30 秒，可设 5–300 秒），电压按“电压更新间隔”（默认 1 秒，可设 1–60 秒），只读取已开启的卡片；每条指令插到指令队列最前、不重试，最多占用九号指令分发器 1 秒；先经车型配置的 `hasCommand` 过滤，车辆未连接或投屏结束时停止，不写入任何设置。卡片不再显示“多少秒前更新”：胎压超过 2 倍胎压间隔、电压超过 5 倍电压间隔没有收到新数据时，对应数值直接显示为 `--`，不会显示编造或过时的数值；设置对话框会提示对应的秒数。关闭“主动读取”后只显示九号自行读取的数据，过期规则相同。“关于”里解锁调试模式后另有“寄存器探测”开关（默认关）：勾上后在投屏或虚拟显示器运行期间轮流读取 App 自己不展示的状态寄存器（每 250 ms 一个），并在画面左侧画一张表——寄存器名、最近一次回复的字节、几秒前更新；正在读取的行用琥珀色标出，3 秒内值有变化的行用绿色标出，无回复的灰显。旁边的“设置”可勾选探测哪些寄存器（含全选/全不选，勾得越少刷新越快），还可以开启“全索引扫描”：模块把 dis/ecu/mcu 板 0–255 每个索引的两字节读取指令注入九号自己的指令表（只在本进程内、只读），一个一个读完整个索引段；表格放不下时只显示最近变化过、其次是最近有回复的寄存器，无回复的索引两次后自动跳过。值变化同时写入日志 `PROBE 名称 bytes=… (was …)`。用途是在真车上换挡、倒车（R）、坡道驻车（H）时找出跟随这些状态的寄存器，找到后再做成控件。M5 P（车型 14103）没有电池温度指令，卡片不显示电池温度。车辆之间的数据分开保存于内存，投屏期间固定展示启动时所选车辆；电压曲线只保存在内存中，会话之间保留，超出 60 秒的样本丢弃。

“控件管理”分别控制手机状态、胎压、电压、音乐、通知和音量，保存后立即应用，也会保留到下次启动；胎压、电压、音乐、通知行尾各有“设置”按钮：胎压设置前后胎，电压、速度、功率各自设置曲线图和曲线时长，读取间隔集中在“数据读取设置”，通知打开通知设置；每行的“条件”按钮设置显示条件。关闭控件后不保留其布局空位或触摸拦截区域。手机状态在双卡时与其他卡片同宽（190，两张卡从左边排起），只有一张卡或无卡时按内容变窄并靠右对齐；音乐、胎压和开了曲线图的电压固定为 190 宽，关闭曲线图的电压按内容模板取窄宽度，数值变化不会改变卡片宽度；音乐未播放时不显示。所有卡片的出现、消失、位置和尺寸变化都以约 0.3 秒的缓动动画过渡。通知还需要通知设置中的总开关、应用勾选和系统通知使用权；重新启用不会重放关闭期间的消息。“音量”控件在手机任一音量（媒体、铃声等）变化时，于画面左下角车机音量图标上方从左侧滑入一条竖向音量条和百分比，约 2 秒后向左滑出；连续按键只延长停留并平滑改变填充高度，不拦截触摸；模块只读取音量等级，不读取音频内容。旧版本保存的控件设置升级后会自动打开新增的曲线图、音乐自动隐藏和音量开关，其余选择保持不变；早期的“主动读取”开关已取消，卡片开启即读取。

模块启动时按内置的目标表校验所需的九号类、方法和布局资源（`HOOK CHECK` 日志），结果也显示在设置页底部的状态文字里；九号升级后能直接看到缺失了哪一项，而不是静默失效。

这些控件合成到虚拟屏与系统录屏的最终供帧画面，手机预览显示相同样式。没有投屏时预览还会在最上层画出车机自己叠加在画面上的卡片示意（右上角那块带挡位、km/h、功率、续航、电量的仪表卡片），位置来自同一份投屏配置里 `layout.baseMap.uiStyle.boundRects` 中由仪表自己绘制的矩形（M5P 为 (641,44)–(841,258)），没有配置时按实拍标定的 (640,44)–(842,254)；控件溢出到左列的判断也用同一组矩形。便于看清哪些内容会被车机遮住；这一层只画在手机预览上，不会进入发送给车辆的画面。调试标定模式仍只显示坐标图。通知内容仅在内存中短暂保存，通过现有校验 UID 的模块连接传给九号，不写入日志或磁盘。通知抬高控件后，控件可能进入原车 Overlay 的范围，原车叠加的信息仍可能覆盖它们。虚拟屏预览工具栏的“通知”按钮（只在虚拟显示器预览的工具栏里）弹出一条模块自己生成的示例通知，时长、宽度和条数都跟随通知设置，用于检查通知的位置、宽度和字号；它不经过通知监听器，不需要通知使用权和“显示通知”总开关。

## 统计与诊断

在设置中打开“统计信息”。每次新投屏重新计数，结束后保留本次累计值；实时速率使用最近约两秒的采样窗口。

| 指标 | 含义 |
| --- | --- |
| 画面采集 | 虚拟屏或系统录屏收到并转换为 Bitmap 的 RGBA 帧数及帧率 |
| 编码器供帧 | 模块向原捕获流程提供画面的次数 |
| 编码输出 | 命中的编码监听回调次数、数据量及码率 |
| RTP 发送帧 | 观察到的不同 RTP 时间戳结束标记数 |
| 发送帧 | 交给原发送器（分片前）的编码帧数、数据量及速率 |
| 发送提交 | 最后一跳（Wi-Fi UDP 数据报或蓝牙 GATT 写入）的 RTP 包数、字节数及速率 |
| 链路反馈 | 原发送队列放弃的帧数、仪表通过 RTCP 报告的丢包次数、接收报告的丢包率与累计丢包，以及仪表请求的码率 / 帧率 |
| 原会话编码配置 | 原捕获参数、编码请求与输出分辨率、目标 FPS、码率和实测编码速率 |

未命中兼容接口时显示未读取状态。发送提交表示调用发送方法，不代表仪表已收到或显示，也不等同于蓝牙空口吞吐量。目标 FPS、实际采集 FPS 和编码 FPS 分别统计。

“设置覆盖”对话框里勾选“预览统计”后，手机预览左上角实时显示码率、带宽、帧率 / 目标帧率、帧数、丢帧和丢包；未投屏时只显示采集帧率和帧数。勾选“覆盖码率”或“覆盖帧率”并保存后，车辆投屏的编码器改用滑块值：码率立即生效，帧率从下一次取图开始生效；不勾选时沿用仪表配置文件里的值。覆盖只作用于车辆投屏的编码器，不改变蓝牙指令，也不改变仪表端。

车辆投屏运行至少 10 秒后，在设置中打开“日志”，点击“分享完整日志”，通过系统分享窗口发送或保存 UTF-8 `.txt` 文件，不再复制到剪贴板。文件包含导出时两个进程当前保留的日志、连接状态及原会话编码配置，不再额外按 96,000 字符截断；进程重启前或环形缓冲区已淘汰的事件无法恢复。生成文件需要模块服务可连接；连接异常时仍可打开本地摘要。

`ENCODING CAPTURE` 记录原参数，`CONFIG` 记录编码请求，`OUTPUT` 记录输出格式，`RATE` 和 `STREAM` 记录实测速率。停止后仍可分享本次配置，直到下一次启动。日志不记录画面、输入文字或编码载荷。实现细节见 [架构与统计](architecture.md)。

设置底部依次为“关于、日志、关闭、保存”。“关于”显示版本、开源许可证及第三方声明，许可证全文可离线阅读。

## 构建

需要 JDK 17+、Python 3.11+、Android SDK Platform **36.1** 和 Build Tools **37.0.0**。Gradle Wrapper 为 **8.13**，AGP 为 **8.13.2**。

配置 `JAVA_HOME` 和 `ANDROID_HOME`，或在 `local.properties` 中设置 `sdk.dir` 后执行：

```sh
./gradlew :app:assembleDebug
```

Windows 使用 `gradlew.bat`。开发 APK 位于 `app/build/outputs/apk/debug/`，使用调试签名。

发布构建统一使用 `scripts/build.py`。首次使用自己的密钥构建：

```sh
python scripts/create_signing_key.py --jdk "$JAVA_HOME"
python scripts/build.py --sdk "$ANDROID_HOME" --jdk "$JAVA_HOME" --allow-other-signer
```

PowerShell 使用 `$env:JAVA_HOME` 和 `$env:ANDROID_HOME`。`--allow-other-signer` 允许开发者使用自己的证书，签名不同的 APK 不能覆盖官方签名的安装。维护者使用原发布密钥时省略此参数，保留证书校验。

构建脚本校验依赖、编译源码、运行主机测试、打包签名并核对 APK 的包名、版本、作用域、必要类与签名。结果输出到 `dist/`。源码归档和发布流程见 [发布说明](release.md)。

## 使用限制

- 独立副屏使用原应用的数据，不是应用分身；应用的方向、窗口、输入法与后台行为受系统和应用实现影响。
- 系统录屏遵循 Android 的录制限制，受保护窗口可能显示为空白；录屏模式不支持手机锁屏后继续采集。
- 仪表编码尺寸和目标帧率沿用九号原会话参数，修改虚拟屏尺寸或采集目标不会直接修改车辆编码配置。
- 手机预览正常时，仪表仍可能有延迟或卡顿；现有统计无法测得仪表实际显示时延。
- 主机测试和构建检查不代替不同手机、授权后端及车辆的实测。
